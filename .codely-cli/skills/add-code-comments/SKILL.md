# 添加零基础注释

为工程源码添加零基础中文注释时，严格遵守以下四条硬性规则并执行保真工作流。

## 四条硬性规则

1. **零基础标准**：假设读者完全没学过编程。`#include`、包含保护、`enum`、`class`、`private/public`、`static`、`virtual`=0 纯虚函数、虚析构、指针、构造/析构函数、单例等每个语法构件都要解释"是什么、为什么存在"。
2. **逐词解释**：拆解每一行的每个符号的含义与作用（如 `m_` 匈牙利前缀、`::` 作用域解析符、`->` 与 `.` 的区别、`+=`/`++`、`&&`/`!`、`|` 按位或、`(int)` 参数、`return`、流插入 `<<`、条件编译等）。
3. **只准新增注释，严禁修改源码**：一行原代码都不许改动——包括行尾空格、空行数量、文件末尾换行符个数（部分原文件结尾没有换行符）；原有英文注释原样保留，在旁边另加中文翻译；原作者的分隔线注释（如 `//---...`）宽度不得加长或缩短。
4. **详解文件间联系**：每个文件头部用注释块说明——本文件的作用、谁包含它（#include）、它包含谁、谁调用它；入口文件（main.cpp 类）额外加"全工程文件地图"ASCII 关系图与"一次完整执行的调用流程"。

## 注释编写规范

- **只写独立注释行**（新起一行，置于被解释代码上方），不往原代码行尾追加注释——保证 git diff 是纯新增（0 删除）。
- 文件头总览块用 `//====...====` 框；函数/关键段落说明用 `//----...----` 分隔。总览块结构：本文件作用 → 与相关文件的逐个关系 → 相关"C++ 小课堂"或业务规则速查。
- 同一语法点在多个文件重复出现时，只在第一次出现处详尽解释，后续文件写一句"原理详见 XX 文件中的注释"，避免冗长重复。
- 只用 `//` 行注释，不用 `/* */`；注释行末尾禁止出现反斜杠 `\`（行拼接会把下一行源码吞进注释）。
- 风格基准：已完成注释的 `Buckland_Chapter2-State Machines/WestWorld1/` 全部 10 个文件是本仓库的标准范例——main.cpp 看"文件地图 + 调用流程"写法，Locations.h 看包含保护/枚举详解，MinerOwnedStates.h 看"状态切换全景图"。模仿其结构与口吻，不要照抄内容。

## 保真工作流

1. 注释前先 `read_file` 读原文，逐行复刻原行（read_file 显示的行尾空格必须原样保留），只插入注释行。优先按"小头文件 → 基类 → 核心类 → 大实现文件 → 入口文件"顺序逐个处理。
2. **每写完一个文件立即校验纯增量**：`git diff --numstat -- <file>` 第二列（删除数）必须为 0；`git diff -U0 -- <file> | rg "^-[^-]"` 输出必须为空。
3. 若出现删除行，定位原因修复：常见原因——漏抄原空行、原分隔线宽度被改动、原行尾空格丢失、误"修正"了原代码。用 `git cat-file -p "HEAD:<路径>"` 对照原版逐字节还原（只许还原原文，不许修改它）。
4. 全部文件注释完成后，运行下方编码归一化脚本，统一编码/行尾并复核纯增量。
5. **编译验证**：用 MSBuild 重新编译该工程（Debug 与 Release 都要），必须 0 错误 0 警告；若出现 C4819 编码警告，说明编码归一化未生效。
6. 边界：公共共享目录（如 `Common/`，被多个章节引用）未经用户明确要求不改动、不加注释，其作用在引用它的章节文件注释里解释；非源码文件（.sln/.vcxproj/.filters/.user 及 Debug/、Release/、.vs/ 等产物）不处理。

## 编码归一化脚本

write_file 写出的文件是 UTF-8 无 BOM + LF 行尾；本仓库磁盘文件要求 UTF-8 BOM + CRLF（保证 VS 2026 编辑器与 MSVC 正确显示中文、无 C4819 警告），且文件末尾换行符个数必须与 git HEAD 原版完全一致。

注释全部写完后，在仓库根目录执行（`<files>` 为本批全部注释文件，路径相对仓库根）：

```
powershell -NoProfile -ExecutionPolicy Bypass -File ".codely-cli/skills/add-code-comments/scripts/normalize-verify.ps1" <file1> <file2> ...
```

脚本自动完成：逐文件按 git 检测目标行尾（w/crlf 或 w/lf）、LF↔CRLF 转换、按 HEAD blob 对齐末尾换行符个数、加 UTF-8 BOM；最后打印每个文件的 git diff 增删统计，任一文件删除数 > 0 即 FAIL（退出码 1），必须修复后重跑。

## 注意

- Windows PowerShell 5.1 不支持 `&&`，多条 shell 命令用 `;` 分隔。
- 项目源文件均为 MultiByte 的 VC6/VS2008 转换工程，中文注释只出现在 `//` 注释里，不出现在字符串字面量中。
